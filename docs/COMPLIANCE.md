# Легальность и отсутствие искажения Метрики/Вебмастера

## Почему официальные API вместо антидетекта

Классический «антидетект» для проверки позиций (stealth-браузер, ротация
фингерпринтов Canvas/WebGL/Fonts/UA, резидентные прокси, эмуляция мыши/скролла)
строится ради **обхода антибот-систем Яндекса**. Это:

- **нарушает ToS Яндекса** и условия использования поиска;
- **хрупко** — ломается при каждом обновлении антибота, требует постоянной гонки;
- **даёт грязные данные** — часть запросов ловит капчу/подмешивает рекламу, позиции
  «плавают», выборка нерепрезентативна;
- **создаёт юридический и репутационный риск** для сервиса `pf.sites-s.ru`.

Поэтому сервис использует санкционированные источники:

| Задача | Источник | Ссылка |
|--------|----------|--------|
| Позиции в выдаче | Yandex Search API v2 | https://yandex.cloud/ru/docs/search-api/ |
| Частотность | Wordstat API | https://yandex.ru/dev/wordstat/ |
| Скорость (LCP/FCP/TTFB) | PageSpeed Insights API | https://developers.google.com/speed/docs/insights/v5/get-started |
| Конкуренты, видимость | Keys.so / Serpstat / Ahrefs API | офиц. документация провайдеров |

Search API возвращает выдачу официально, с указанием региона (`lr`), устройства и
глубины — без визитов на чужие сайты и без обхода защиты.

## Почему данные не искажают Метрику и Вебмастер

### 1. Позиции — ноль визитов на ваш сайт
Позиции получаются запросом к **API Яндекса**, а не переходом бота из выдачи на сайт.
Следовательно, в Метрике вашего сайта **не появляется ни одного визита** от проверки
позиций. Вебмастер тоже не видит аномального трафика.

### 2. Краулер аудита — идентифицируемый и отфильтровываемый
Аудит ходит **только по вашему сайту** (который вы подтвердили как владелец), с:

- фиксированным `User-Agent`: `PF-SiteAudit/1.0 (+https://pf.sites-s.ru/bot)`;
- заголовком-маркером `X-PF-Audit: 1`;
- соблюдением `robots.txt`;
- лимитами: 10–15 страниц за сессию, задержка между запросами, ограниченная глубина.

**Настройка фильтра в Яндекс.Метрике:**
`Настройки → Фильтры → Добавить фильтр → «Не учитывать роботов» →` по User-Agent,
маска `PF-SiteAudit`. После этого визиты аудита не попадают в отчёты.

Так как краул малостраничный и с задержками, он не создаёт нагрузку, которую
Вебмастер расценил бы как аномалию сканирования.

### 3. Что сервис НЕ делает
- не накручивает поведенческие факторы;
- не имитирует живых пользователей в выдаче;
- не скрывает свою природу от Яндекса;
- не хранит чувствительные артефакты обхода (фингерпринты, IP-пулы) — их просто нет.

## Ответственность пользователя
- Подтвердите право на аудит сайта (владение доменом / доступ в Вебмастер).
- Соблюдайте лимиты и ToS провайдеров API (ключи — ваши).
- Конкурентов анализируйте только по публичным данным провайдеров, без краула их сайтов.
